# PreciseKit v0.5.2 — security, CI and release plan

Target: 0.5.1 → 0.5.2, on `master`. Preserve public APIs, errors, ESM/CJS/types,
Node >=18 package support and zero runtime dependencies. No commit, push, tag,
GitHub release, publish or deployment without maintainer approval.

## Implementation sequence

1. Inspect repository rules, affected source/tests, workflows and available remote evidence.
2. Replace the three date/number ReDoS mechanisms with bounded or linear processing;
   add adversarial regressions while preserving formatting and errors.
3. Replace both FAQ tag-removal sites with a shared linear extractor; retain
   single entity decoding and script-context JSON encoding, test nested delimiters.
4. Repair only evidenced workflow/publishing defects; document inaccessible evidence
   and required npm/GitHub configuration without claiming historical runs repaired.
5. Synchronize 0.5.2 manifests, changelog, README and generated documentation.
6. Run install, focused regressions, check, package/docs/site/Bun/tarball gates,
   audit and pack inspection. Record real outcomes and measured bundle changes.
7. Review diff; provide release commands and external verification checklist for approval.

## Compatibility and risk

- Date/number parsing and exact decimals are public contracts: preserve accepted
  inputs, precision, padding, time zones and error codes; test existing oracle suites.
- FAQ extraction is for repository-owned fragments, not a general HTML sanitizer.
  Generated JSON-LD must escape `<` independently after entity decoding.
- OIDC identity and npm Trusted Publisher validation require external evidence and
  a successful authorized publish; local checks cannot prove those conditions.

## Evidence and verification

Implementation findings, actual command outcomes and external blockers are recorded
in `plans/v0.5.2-security-ci-release-report.md` after verification.
