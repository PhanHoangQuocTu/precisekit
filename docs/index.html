Quick start

Every utility is a named export, so imports stay focused. Results below are what the code returns.

Exact decimal math

import { divide, summary, round } from "@fatdevcon/precisekit";

summary(0.1, 0.2);                 // 0.3
round(1.005, 2);                   // 1.01
divide("1", "3", { precision: 5 }); // "0.33333"
summary("100000000000000000000000", "1");
// "100000000000000000000001"

Format for a real user

import { formatCurrency, formatBytes } from "@fatdevcon/precisekit";

formatCurrency("12345678901234567890.129", "USD");
// "$12,345,678,901,234,567,890.13"
formatCurrency(1234.5, "VND", "vi-VN"); // "1.235 ₫"
formatBytes(1536, { base: 1024 });      // "1.5 KiB"

Dates in any time zone

import { formatDate, addMonths } from "@fatdevcon/precisekit";

formatDate(new Date("2026-01-15T17:30:00Z"), "yyyy-MM-dd HH:mm xxx", {
  timeZone: "Asia/Ho_Chi_Minh",
}); // "2026-01-16 00:30 +07:00"
formatDate(addMonths("2026-01-31", 1), "yyyy-MM-dd"); // "2026-02-28"

Retry flaky work

import { withRetry } from "@fatdevcon/precisekit";

const config = await withRetry(() => fetch("/config.json").then((r) => r.json()), {
  retryCount: 3,
  delay: ({ count }) => 200 * 2 ** count,

Common tasks

Short answers to questions developers search for, using only exported APIs.

How to group data in JavaScript

import { groupBy } from "@fatdevcon/precisekit";

const byRole = groupBy([
  { name: "An", role: "dev" }, { name: "Binh", role: "qa" },
], (user) => user.role);
// { dev: [{ name: "An", ... }], qa: [{ name: "Binh", ... }] }

How to avoid floating-point errors when adding money

import { sumValueInArray, multiply } from "@fatdevcon/precisekit";

sumValueInArray([19.99, 5.01, 0.1]); // 25.1
multiply("19.99", 3);                // "59.97"

How to format a time zone-aware date

import { getTimeZoneOffset, formatInTimeZone } from "@fatdevcon/precisekit";

const instant = new Date("2026-01-15T12:00:00Z");
getTimeZoneOffset(instant, "Asia/Ho_Chi_Minh", { unit: "hours" }); // 7
formatInTimeZone(instant, "Asia/Ho_Chi_Minh", "en-GB", {
  dateStyle: "short", timeStyle: "short", hourCycle: "h23",
}); // "15/01/2026, 19:00"

How to parse a file size or duration string

import { parseBytes, parseDuration } from "@fatdevcon/precisekit";

parseBytes("1.5 GB");        // 1500000000
parseBytes("512 KiB");       // 524288
parseDuration("1h 2m 3s");   // 3723000
parseDuration("2 days, 4 hours"); // 187200000

How to update nested state without mutating it

import { setByPath } from "@fatdevcon/precisekit";

const state = { user: { name: "An", tags: ["a"] } };
const next = setByPath(state, "user.tags[1]", "b");
// next.user.tags is ["a", "b"]; state is unchanged

How to format very large currency values

// "$12,345,678,901,234,567,890.13"

Frequently asked questions

How do I avoid floating-point errors like 0.1 + 0.2 in JavaScript?

Use summary, subtract, multiply, divide and round. They calculate in exact decimal arithmetic, so summary(0.1, 0.2) is 0.3 and round(1.005, 2) is 1.01. Pass bigints or numeric strings when values exceed 2^53.

Does it have dependencies?

No. Since 0.3.5 the package has zero runtime dependencies. decimal.js and date-fns are development-only test oracles.

Does it support TypeScript, ESM and CommonJS?

Yes. It ships ESM, CommonJS and type declarations, and public option and result types are exported alongside the functions.

Which runtimes are supported?

Node.js 18 and newer, Bun, and modern browsers. Formatting and time zone helpers use the standard Intl APIs, so output follows the runtime's locale data.

Can it replace decimal.js, big.js, date-fns or lodash?

For many everyday cases, yes: exact arithmetic with rounding modes, ISO parsing, token formatting and common collection helpers are covered. It is a focused toolkit, not a full replacement. Libraries with broader scope, such as complex date arithmetic or arbitrary-base numbers, still fit those jobs better.

Does formatDate use the same tokens as date-fns?

It supports a documented subset, including yyyy-MM-dd HH:mm:ss, EEEE, do, xxx and PPpp, and accepts a date-fns locale object as options.locale. It is not a complete date-fns replacement; locale-sensitive output depends on runtime ICU data and the selected locale.

Is it tree-shakeable?

Yes. The package is side-effect free and every utility is a named export, so bundlers drop what you do not import.
